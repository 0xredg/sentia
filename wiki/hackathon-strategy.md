# Hackathon Strategy

## Goal

Position Sentia as a Mini App that could only make sense on World.

The strongest version of the story is not "a marketplace for microtasks."

The strongest story is:

Sentia turns World into a live network of verified humans that apps and AI systems can query when machine intelligence is not enough.

## Why Sentia Fits World

Sentia maps naturally to the World stack:

- World ID proves each responder is a real, unique human
- World wallet enables instant crypto rewards after task completion
- World App provides a mobile-first distribution surface
- World Chat can power task notifications, engagement, or follow-ups

This gives a direct answer to "why World?":

Because Sentia depends on verified uniqueness plus instant global payouts.

## Best Hackathon Wedge

For the hackathon, Sentia should not try to show every long-term use case.

The best wedge is:

- a simple human judgment request flow
- completed by verified humans only
- answered quickly on mobile
- rewarded instantly on completion

This makes the product easy to understand in under 10 seconds.

## Recommended MVP

### Core flow

1. A requester submits a task that AI cannot reliably solve
2. The task is routed to verified humans
3. A verified human answers inside the Mini App
4. The answer is returned immediately
5. The responder is paid instantly

### Suggested demo task types

- content safety edge case
- nuance-based sentiment or intent judgment
- qualitative user feedback
- one-human-one-vote or one-human-one-decision action

Use a task where human judgment is obviously better than AI.

## Feature Priorities

### P0

- World ID gated participation for workers
- task creation flow
- task response flow
- instant reward or payout simulation
- clear result screen for the requester
- clean mobile UX

### P1

- response quality controls
- task status states: open, in progress, completed
- simple dashboard for requesters
- latency messaging such as "answers in seconds"
- World Chat notification or engagement loop

### P2

- multiple workers per task
- consensus or confidence scoring
- worker reputation
- API framing or developer mode
- richer analytics

## What To Avoid

- generic crypto UX with too much wallet jargon
- overbuilt marketplace mechanics
- too many modes, personas, or screens
- anything that makes the demo slower or harder to explain
- forced use of World features with no product reason

## Demo Narrative

The demo should communicate three truths quickly:

- this answer came from a real person
- this task is hard for AI and easy for the right human
- the response and payment happened fast enough to feel programmable

## Suggested Product Positioning

### Short version

Sentia is the human intelligence layer of World.

### Hackathon version

Sentia lets apps and AI systems call verified humans on demand through a World Mini App.

When AI hits ambiguity, the task is routed to real people, completed in seconds, and paid instantly.

## Best Story For Judges

The judging panel should leave with this conclusion:

Sentia is not just using World ID because it is available.

Sentia becomes possible because World combines proof of humanity, global distribution, and built-in payments.

## Build Principles For Agents

- optimize for a strong 3-minute demo, not feature breadth
- prioritize clarity over system complexity
- every major screen should reinforce the World-native thesis
- keep onboarding friction low for mainstream mobile users
- if time is tight, fake scale before faking product logic

## Success Criteria

By submission time, the project should be able to show:

- a working or convincingly demoed Mini App
- a clear use of World ID
- a credible reward flow
- a polished mobile-first user journey
- a pitch that explains why Sentia belongs on World specifically
